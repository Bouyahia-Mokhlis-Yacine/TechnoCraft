# SATIM continuous learning backend

`src.continuous_learning.service.LearningService` is the server-side contract. There are no new HTTP routes or UI. The existing competition, simulation, replay, import snapshots, and incident workflow can continue to operate independently.

## Authentication and storage

Instantiate the service with `resolve_identity(credential) -> Actor | None`. The application server resolves an opaque, validated session or internal worker credential using its existing account and permission store. Map access to `Actor(user_id, role, merchants)` with role `reviewer` or `supervisor` and a server-owned merchant set. Set `merchants=None` only for a deliberate fleet-wide grant. Never deserialize an Actor supplied by the browser. Revalidate the account for every call, as the existing Next.js session code does. Reviewer permissions and supervisor privileges should be mapped explicitly in the adapter. An expert cannot approve their own label.

The default database is `runs/continuous_learning/ledger.sqlite3`. An override must use a dedicated directory named `continuous_learning`. Give write access only to the trusted backend and keep its SQLite database and serialized model artifacts private. Use the same compatible Python and package versions for training and scoring. Keep the existing append-only operational review ledger for acknowledgment, assignment and closure. Feedback history is an independent ledger.

All dates below use `YYYY-MM-DD`. Review coverage is one complete merchant-day per record. Multi-day evidence can be captured with separate revisions for each observation. Audit timestamps are server UTC. An exclusive `as_of` includes only earlier UTC dates, and current corrections can supersede prior admission. Request bodies contain no credentials, actor fields, PANs, transaction identifiers or model blobs. The adapter can map authorization errors to 401 or 403, unknown keys to 404, stale state/revisions to 409, and malformed requests to 422. Serialize only the documented return values and safe error messages.

## Review and monitoring contracts

- `ingest_import(credential, run_id, corrections=[])` returns `{inserted}`. Fleet supervisor or trusted import worker only. Pass a successful **complete** import run ID after all merchants for a date have been ingested. The adapter checks source hashes and reconstructs the closed roster using the existing loader. Dates through the last official observation, mixed/partial batches, and batches with unassignable rows are excluded. Corrections use `[{merchant_id,date,expected_revision}]` and make prior feedback stale. A scored date cannot receive new merchant-days.
- `score_operational_batch(credential, observation_day)` returns `{date,model_id,rows_scored}`. Fleet supervisor or worker only. Score complete batches in observation-date order. The service persists predictions and the incident checkpoint. The import snapshot continues to reflect the frozen import scorer.
- `operational_predictions(credential, observation_day)` returns `{date,model_id,rows}`, scoped by merchant. Each row contains `merchant_id`, `observation_revision`, `superseded`, the evidence fields below and per-metric realized forecast `{error,covered_90}`. `forecast(credential, merchant_id, origin)` returns `{model_id,reference_version,forecast,intraday_hourly_weights}` with seven-day probabilistic forecasts and a 24-element weekday activity profile or null when unsupported.
- `review_queue(credential, observation_day)` returns an array of `{merchant_id,date,observation_revision,incident_id,channel,symptom,selection_reason,priority,selection_probability,random_pool_size,model_evidence}`. The global supervisor creates the daily assignment once, in order, after scoring. Subsequent reads are merchant-scoped. The configured random slots are sampled uniformly from the apparently normal pool before the targeted assignments. Probabilities are conditional on that pool and null for targeted assignments. A selected incident is omitted from future queues. Corrected observations can be reviewed directly using their new revision.
- `submit_feedback(credential, merchant_id, observation_day, label, notes, evidence=[], category=null, expected_revision=0, observation_revision)` returns `{revision}`. Pass keyword arguments in Python. The labels are `confirmed_anomaly`, `verified_normal`, `legitimate_change`, `data_quality_issue` and `insufficient_evidence`. `evidence` is a list of up to 10 short sanitized notes or internal evidence references. A correction supplies the current `expected_revision`; it creates a new pending revision. Submitting the same content against the current revision returns that revision.
- `decide_feedback(credential, merchant_id, observation_day, revision, decision, reason)` returns no body. A supervisor in scope may mark the latest pending revision `approved` or `rejected`. A new review is required to revisit either decision.
- `feedback_history(credential, merchant_id, observation_day)` returns revisions with reviewer, timestamps, category, notes, evidence, model/reference versions and decision history. `feedback_statistics(credential)` returns `{total,current_labels,approval_statuses}` for the current observation revisions in scope.
- `training_eligibility(credential, as_of)` returns `[{merchant_id,date,eligible,reason,observation_revision,feedback_revision}]`. Possible reasons include `eligible`, `reserved_evaluation`, `incident_or_recovery`, `data_quality`, `missing_lifecycle`, `unresolved_collective_candidate`, `awaiting_approved_feedback`, `feedback_changed` and an ineligible label.
- `drift_report(credential, baseline_start, baseline_end, recent_start, recent_end)` returns `{distribution_shift,reviewed_performance,policy}`. Each signal carries `{distance,metric,matched_rows,threshold,status}`. Draw investigation attention to `investigate`; `insufficient_support` means no comparable estimate. The separate reviewed subset summary reports sample counts, precision and recall when defined.
- `labelled_export(credential)` returns `{dataset_version,rows}`. Row fields are `merchant_id`, `date`, `label`, `observation_revision`, `feedback_revision`, and `selection_probability`. This export includes approved confirmed anomalies for evaluation and future supervised research. It carries no transaction payload, reviewer notes or identity.

Model evidence uses `model_version`, `reference_version`, `phase`, `incident_id`, `reference_hold`, `symptom`, the two `*_score`, `*_threshold` and `*_flag` fields prefixed by `sequential` and `hybrid`, `ml_tail_rank`, `hybrid_tail_rank`, `collective`, `collective_tail_rank`, `count_residual`, `rejection_residual`, `cancellation_residual`, `forecast_error` and `forecast_covered`. Missing diagnostics are null. Ranks are empirical tail evidence under the calibration population.

## Model management contracts

All model management functions require a fleet supervisor or the corresponding trusted worker.

- `initialize_baseline(credential, reason)` returns `{model_id}` once per registry. It packages the existing archived ordinary training-period operational baseline. The protected archive and configuration hashes are checked. This separate operational copy is the starting champion.
- `start_learning_job(credential, plan)` returns `{job_id,state:"queued"}`. A plan supplies `{fit_start,calibration_start,calibration_end,eval_start,eval_end,refit_isolation_forest:true}`. Reference rows and their approvals must predate `fit_start`. The fitting window is `[fit_start,calibration_start)`, calibration is `[calibration_start,calibration_end]` and evaluation is `[eval_start,eval_end]`. The fit and calibration data must be approved before evaluation and job registration. Use `refit_isolation_forest:false` for a reference update that retains the current Isolation Forest weights and recalibrates fusion on independent data.
- `run_learning_job(credential, job_id)` claims the queued job and returns `{model_id}` or null for a known support failure. Run it in a managed worker process or thread outside the HTTP request. Poll `learning_job_status(credential, job_id)` for state, plan, cutoffs, result or safe failure detail. `cancel_learning_job(credential, job_id)` marks a queued or interrupted run cancelled and prevents publication from a worker that is still finishing. Evaluation windows remain reserved across jobs.
- `shadow_batch(credential, job_id, observation_day)` returns `{date,rows_scored,prospective,scoring_seconds}`. Score the operational batch first with the champion and shadow the same closed roster before anybody submits feedback. Repeat chronologically for the whole declared window. Retrospective replay produces diagnostics but cannot qualify a version for activation.
- `model_comparison(credential, job_id)` returns `{eligible_for_promotion,blockers,champion,challenger,dates_scored,expected_dates,scoring_seconds,label_manifest,estimand,recommendation}`. Metrics include reviewed day and episode performance, workload, persistent sensitivity, delay, drift-cohort false alerts, forecast error and 90% coverage where observed. Missing metrics reflect unavailable data or denominators. Require census review of the declared evaluation window and enough positive, negative and persistent examples before promotion. Stored comparisons and feature manifests remain versioned.
- `decide_model(credential, job_id, decision, reason)` accepts `activate` or `reject`. A successful rejection returns `{model_id,state}`. Activation rechecks the gate against current feedback, observation revisions, and the active champion inside the write transaction. It returns `{active_model,previous_model,effective_day}`. Sequential thresholds stay frozen, and open Directional CUSUM tracks continue with their pinned references.
- `rollback(credential, expected_active, reason)` restores the previous version of the latest activation, with the same result schema as activation. Both actions take effect at the next unscored date after the current UTC day and any already ingested date, whichever is later. Existing checkpoints and sealed outputs remain historical records.
- `model_registry(credential)` returns `{models,approval_history}` with model state, configuration, reference and dataset fingerprints, cutoffs and audit decisions. `training_integrity` on the active model identifies whether its reviewed data and inherited Isolation Forest provenance still qualify. A correction can trigger `recheck_required`. Fitted artifacts stay on the server.

## Frontend and worker handoff

Validate the existing signed session on the server and apply merchant authorization before forwarding any request. Use the queue to present evidence, probability where available, priority and the exact observation revision. Display a separate expert-label form and supervisor approval panel alongside the existing incident actions. Surface each evaluation blocker and make an activation or rollback an explicit supervisor action. Feed imported operational batches through the preceding contracts and keep the official competition downloads on their existing routes.
